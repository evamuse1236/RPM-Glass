# Standalone design: adversarial review B

Read-only review of the proposed design against current code. `D` means `docs/web-standalone/design.md`; other paths are repository-relative. Proposed modules do not exist yet. Scenarios below are design counterexamples, not claims that this protocol is implemented.

1. **Blocker — rebasing every Undo image creates dangling references.** Create and sync Block B, retaining Undo of its creation. Another browser adds task T to B. D:104 adds T to the pre-creation Undo image, which contains no B. Undo restores T without B and fails `validatePlanner`. Evidence: `android-companion/planner-state.mjs:44–49,26`. Reproduced with the actual reducer in memory: “This item no longer exists.” **Smallest fix:** dependency-aware conditional inverses for this case, or explicitly refuse the destructive Undo while retaining recovery; validate every rebased image before exposing it.

2. **Blocker — repair treats incomplete pulls as authoritative deletions.** D:63 paginates records, while D:108 repairs after each pull. A page contains a task referencing B; B arrives next page, or in the next seed batch. Repair clears the valid link and pushes that clearing permanently. A partial routine/run pull similarly deletes history. Evidence: D:60–64,108,121; `body-store.mjs:239`, `planner-state.mjs:26`. **Smallest fix:** stage pulls through a consistent revision boundary before repair; repair only explicit target tombstones, never mere absence from a partial view. Seed completion needs the same barrier.

3. **Blocker — frozen outbox does not protect edits made during delivery.** Freeze title B, then locally change B→C before its reply. D:35 applies incoming B and D:92 clears stamps; no rule rebases the still-dirty C or preserves its timestamp. Backup restore while the old outbox is pending has the same risk (D:93). Current phone saves permit intervening writes through version CAS (`CompanionStore.java:31`). **Smallest fix:** atomically reconcile reply/base/outbox against the latest local version, replay the post-send delta, and clear only acknowledged stamps; specify crash recovery for that transaction.

4. **Blocker — field merge can construct an invalid record from valid edits.** Start with monthly goal period 12. Phone changes it to quarterly/1; browser later changes monthly period to 11. D:80–85 retains quarterly and chooses 11. Actual `validatePlanner` rejects it (`planner-state.mjs:24`); reproduced in memory: “Choose a valid number.” Task repeat/schedule/completion fields have similar coupling. **Smallest fix:** merge invariant groups atomically with conflict preservation, then validate the assembled planner server-side before committing, rather than relying on the single normalization example and client repairs.

5. **Blocker — Capture backend loses the existing CAS guarantee.** Two scheduled Captures load the same account `captureState`. A saves its draft/transactions; B's later whole-state save replaces them. D:113–114 supplies neither expected-version validation nor serialization. Evidence: `intent-v2/src/repository.mjs:8–10,19–31` requires state and receipt in one CAS write; its promise queue is per repository instance. **Smallest fix:** account-scoped durable Capture serialization plus version-checked saves and durable transaction receipts. Paged reads also need a consistent snapshot or revision-checked restart.

6. **Major — scheduled Capture can remain saved forever.** An action fails before marking `sorting`; D:115's cron only repairs `sorting`, so the `saved` row never runs again. A failure after planner commit but before outcome needs reconciliation, not fresh allocation. [Convex scheduled actions](https://docs.convex.dev/scheduling/scheduled-functions#error-handling) execute at most once and are not automatically retried. **Smallest fix:** persist a job claim/attempt generation, recover both unstarted and expired jobs, and reconcile the existing Capture transaction before retrying. Test both failure boundaries.

7. **Major — one web session is not one browser replica.** D:70,127 binds replicas to sessions, but `web/site-worker.mjs:7–8,20–23` deliberately substitutes one Site token for every browser. Two browsers/tabs can share replica identity while keeping independent bases/outboxes and cached task leases. Lease reuse can allocate the same task ID; the collision guard only rejects a create from *another* replica (D:100). **Smallest fix:** register a distinct durable replica/lease per independent local store, under the authenticated session, and coordinate tabs that share storage.

8. **Major — timestamp granularity contradicts recursive merge.** D:83 merges `alertIntent` recursively, but D:92 stamps its whole top-level object. Phone changes alert type at 10:00, browser changes type at 10:30, phone changes only lead at 11:00: the old phone type inherits 11:00 and incorrectly wins. Evidence: `planner-state.mjs:94–95`. Future-clock clamping at upload (D:84) likewise lets an older offline edit appear newest. **Smallest fix:** stamp the same leaf paths the merge compares; define clock uncertainty and an honest deterministic conflict rule instead of promising unknowable real-time ordering.

9. **Major — water identities collapse independent events.** Two offline replicas each log one glass at the same instant: both project `<instant>#0` (D:26). Equal records merge into one glass, losing a real event. Counting duplicates within each array does not distinguish replicas. Evidence: `body-store.mjs:119–123` stores instants without identity. **Smallest fix:** assign durable UUIDs to new glass events; use a stable, one-time migration mapping for historical instants. Test equal instants across replicas, not only within one array.

10. **Major — last-50 receipts are not a durable retry contract.** D:70 forgets old requests without specifying a retired-request rejection or binding IDs to payloads. A restored browser state or shared-session retry after 50 requests can remerge an acknowledged edit and duplicate conflict notes. Server Capture Undo additionally references an undefined `yield` policy absent from `Change` and the merge rules (D:59,104,116). **Smallest fix:** monotonic per-replica sequence/high-water rejection, payload identity checks, and an explicit conditional-Undo operation with repeated-request tests.

11. **Major — count-based Capture pruning cannot meet Convex storage limits.** D:113 keeps 50 captures/drafts in `captureState`. Thirty valid 12,000-character three-byte captures already exceed 1 MiB before drafts and transactions. Evidence: `intent-v2/src/harness.mjs:27`; [Convex document limits](https://docs.convex.dev/production/state/limits#documents). Pruning by recency also evicts still-unanswered drafts, which current capacity permits up to 100 (`intent-service.mjs:19,28`). **Smallest fix:** separate bounded documents for Capture state/receipts; retain active drafts and raw words independently of cache eviction; enforce byte budgets.

12. **Major — migration discards durable unsent intent.** D:122 displays old queued work once and deletes its keys. Reload after that loses unacknowledged changes, original Capture text, and recovery. Evidence: `web/app/client.mjs:21–27` persists complete command payloads; `plan-queue.mjs:38–46` persists the replay records. Checking server pending commands once (D:120) also fails to fence old clients submitting afterward. **Smallest fix:** retain/export the complete old outbox until explicitly recovered or migrated, fence old writes, and mark seeding complete only after every seed batch is acknowledged.

13. **Major — landing checks cannot establish native convergence.** D:136–143 tests one Capture in India time, unrelated-edit Undo, a stand-in reconnect, then existing emulator scenarios. None requires a real headless phone pull→save→reproject round trip, same-field Undo, interrupted migration, shared-Site browsers, or the counterexamples above. `CompanionActivity.java:129`, `PlannerCommandHost.java:57`, and `NotchRunner.java:217` are distinct save bridges. **Smallest fix:** add these cases before deleting the old protocol; explicitly pass origin through every bridge and test repair-generated changes retain stamps. A simpler option is browser/server reducer commits directly in Convex, with only the offline phone needing state reconciliation; optimistic browser replay already exists in `plan-queue.mjs:104–115`. It removes browser replica/lease machinery while preserving phone-offline website writes.

Validation: two targeted Node checks executed entirely in memory; no repo files edited, full suite/build/deploy not run.
