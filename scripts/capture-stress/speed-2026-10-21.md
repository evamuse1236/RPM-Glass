## Findings and changes

- The live system prompt is 31,341 UTF-8 bytes, larger than the brief’s historical ~20 KB estimate. Before caching, every request reported zero cache reads. Both Anthropic and the OpenRouter Claude path now send the unchanged system text as a text block with an ephemeral cache marker. Warm Anthropic calls read 12,922–12,923 prefix tokens. OpenRouter forwards this marker according to its [caching documentation](https://openrouter.ai/docs/guides/best-practices/prompt-caching); live fallback remains UNVERIFIED. Caching alone gave a modest quick-route change and did not fix long-route latency.
- A focused draft or open question selects careful/high; the broad contextual-follow-up expression can also match words inside a standalone ramble. At 1,500+ characters that previously selected long/high. Both monologues took 32.6–42.1 seconds and used 7,644–8,554 output tokens for 4,657–5,077 text characters. Extra reasoning is the likely main cost, not just prompt ingestion; the API does not expose a separate thinking-token count here.
- A separate controlled replay with thinking off passed both monologues in 6.369/6.407 seconds of backend time (2 calls, $0.002751). The final production policy therefore uses long/none with the existing 16,000-token allowance. Explicit long draft/open-question replies retain high effort via longCareful. Short careful replies, hard requests, escalation, repair, semantic validation, saved words and Undo remain in place. Final monologues passed in 4.889/5.653 seconds per API call.
- The initial focused deletion produced an invalid discard identity, then one Sonnet repair also failed semantic checks. Cache and final phases each succeeded with one careful call. This is model variability, not evidence that caching fixes deletion. There were no escalations in these workloads. Valid JSON alone is not a successful capture.
- Quick responses used only a few hundred output tokens, below their 4,000-token allowance. Lowering maxTokens would risk truncation without shortening already-complete replies. reply preserves acknowledgements and questions; card supports queries; decisions and evidence preserve coverage and safety. No schema fields, prompt rules, prompt text, UI, capture-agent commit gating or draft-actions were changed. Prompt removals: none.
- Mercury 3 is an opt-in quick route: change QUICK_CAPTURE_MODEL to MERCURY_MODEL in intent-v2/src/model-policy.mjs. Haiku remains default. The native OpenRouter allowlist permits 4,000 tokens and a 17-second read cap for its 15-second route. Its strict schema uses providerSchema, still validated against TURN_SCHEMA locally, and Claude provider pins are removed. [OpenRouter confirms Mercury JSON-schema output support](https://openrouter.ai/inception/mercury-3).
- Mercury comparison: **not run: no key** (OPENROUTER_API_KEY is absent). compare-models.mjs is ready: --n 10 --budget 0.5, same fixed cases and inputs, per-call schema-validity rate, per-case existing-check pass rate and latency. Both quick models get 4,000 tokens, thinking off and their own quick deadlines; repairs stay on the compared model. Local readers remain active. A conservative reservation limits spending before every request. The comparison script was exercised with fixtures, not a live Mercury provider.
