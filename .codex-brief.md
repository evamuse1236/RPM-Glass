## Build (Node 22, ES modules, no dependencies unless unavoidable)
1. `bridge.mjs`: long-polls Telegram `getUpdates` (timeout 50 s, offset tracking persisted to a small state file), ignores every chat except `ALLOWED_CHAT_ID`, spawns ONE long-lived Pi RPC child (restart with backoff if it exits), sends each allowed message as a prompt, collects the reply events, and sends the final text back with `sendMessage` (split at 4,000 chars). One message at a time (queue). Reads the bot token from a file path in `TELEGRAM_TOKEN_FILE` and the Anthropic key from `ANTHROPIC_KEY_FILE`; never logs either.
2. Scheduler: a timer that sends configured prompts at fixed local times (Asia/Kolkata), from `schedule.json` (e.g. `[{"at":"08:00","prompt":"Morning briefing"}]`), through the same queue.
3. `extensions/rpm-tool.mjs`: a Pi extension that registers one tool `rpm_today` which GETs `RPM_API_URL + "/v1/today"` with a bearer token from `RPM_TOKEN_FILE` and returns the JSON. The route doesn't exist yet; the tool must return a clear "RPM API not configured" result when the env var is missing.
4. `rpm-bridge.service` (systemd user unit) and `README.md`: install steps on the VM (copy folder to ~/work/telegram-bridge, `vm secret set TELEGRAM_BOT_TOKEN`, set ALLOWED_CHAT_ID, `loginctl enable-linger` needs the user's OK), how to find the chat ID, how to stop it.
