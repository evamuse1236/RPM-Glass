# Memory that earns familiarity

The app remembers with provenance, not with confident guesswork. Maintain separate collections for: user-approved durable preferences; user-approved goals/values; current commitments; temporary working state; unapproved observations. Only approved durable records and currently relevant working state enter normal prompts.

Every durable record has a stable ID, exact source or structured approval event, creation/confirmation date, scope, optional expiry, optional supersedes link and archived flag. Explicit user corrections supersede old claims. A preference is not permission to schedule, message, delete or commit. An inferred pattern is always a hypothesis; ask before promoting it to durable memory.

Show a "Why this?" affordance for meaningful personalization. It should reveal the specific memory used, not an opaque personality score. Support edit, forget and "not today". A one-time override does not automatically rewrite a durable preference. Forgetting excludes the record and linked context from retrieval; clarify separately that archiving is not secure deletion of all raw transcripts/backups.

Rank by relevant topic, focus, confirmation status and freshness. Do not insert all recent memories, or include zero-match biography paragraphs. Prefer small retrieved excerpts to a giant permanent persona prompt. For conceptual synonyms, add a small local lexical index/embeddings later, but evaluate retrieval and privacy on archived/superseded records first.

Sensitive information: do not proactively promote disclosures about health, trauma, sex, finances or other people's private lives merely to improve "friendship". Require explicit review and scoped consent. Never train a user's personality from inferred diagnoses, missing activity logs or apparent moods. Distinguish "the user said they are tired tonight" from "the user is unmotivated".
