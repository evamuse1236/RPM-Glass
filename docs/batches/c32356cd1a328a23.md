## Changes for review

1. Swipe right on a task to archive it; swipe left to open the existing deletion confirmation. Both retain original content, stop active scheduling through the existing archived flag, and offer recovery. Archive and Trash are separate destinations in RPM. Existing deleted records remain in Trash. Task details also expose Archive, so a gesture is not required. Vertical scrolling and short/cancelled gestures do not remove tasks. Repeating entries are archived/deleted as a series.
2. Assistant output uses readable paragraphs, headings, lists, bold text, and inline/fenced code. Rendering uses DOM text nodes, never model-supplied HTML. The compact widget keeps overflow scrollable above the composer. Desktop entry points also serve the shared formatter.
3. Tap the priority badge for an anchored list of positions. Choosing a position uses the existing atomic priority operation and Undo; it never changes scheduled time. Escape, Android Back, outside touch, scrolling, and navigation dismiss the menu. This avoids native select popups that did not appear in the test WebView.
4. The planner title/header now shares the scrolling container with content. Bottom navigation and quick actions remain available. Per-view scroll positions remain separate.
5. Settings → Automation previews demonstrates focus hours, notification batching/release, and X/Twitter blocking with sample events. The policy handles overnight windows, exact domain matching, urgent bypass, and duplicate notification IDs. Equal start/end means no focus period.
6. The same preview demonstrates a configurable verified-feature threshold, mock Hermes preparation, and mock WhatsApp APK handoff. Unverified/duplicate features do not inflate the threshold. Replaying a release is idempotent; a failed attempt retains features and retries with the same request ID.

## Automation boundary

Items 5–6 are review-only simulations, as required by the dispatcher. They have no timers, native notification/accessibility permissions, device policy changes, network calls, live messages, real builds, or publishing. Sample settings and events are intentionally transient. The sample threshold of 3 is editable and is not an activated policy.

Live notification suppression/X blocking requires a separately approved Android integration and its permission/recovery design. Live updates require the actual Hermes contract, feature source, threshold, recipient, signing/build validation, and WhatsApp delivery adapter. No other checkout was edited to supply these dependencies.
