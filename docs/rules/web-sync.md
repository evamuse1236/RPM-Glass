# Web sync rules and what enforces them

Rules for the website, the server hub and the phone's offline replica (`convex/`, `web/`, `android-companion/replica-sync.mjs`, `SyncManager.java`). How it works is in `docs/web-sync.md`. AGENTS.md points here. Add a row when a correction becomes a check.

| Rule | Enforced by |
|---|---|
| The server saves each website change at once; the phone keeps an offline copy that pushes and pulls, and `/v1/planner/sync` answers 410. | `cloud-tests/standalone.test.ts`, `cloud-tests/planner.test.ts` (`retires v1 snapshot upgrades`) |
| When the phone and the website change the same part of a record, the newer change wins and the other version goes into the task's notes and `snapshot.conflicts`. | `cloud-tests/standalone.test.ts` (`merges newer phone values`), `cloud-tests/standaloneEdges.test.ts` (`keeps a newer phone title`), `android-companion/replica-sync.test.mjs`, `web/app/conflict-notes.test.mjs` |
| An edit the phone makes after its outbox froze for a push still meets the conflict rule on the next push. | `android-companion/replica-sync.test.mjs` (`an edit made after an offline freeze`, `a delete made after an offline freeze`) |
| A sync with nothing new on either side writes nothing, and a save that meets a newer version reloads and tries again, three tries at most. | `android-companion/replica-sync.test.mjs` (`an idle sync`), `android-companion/save-retry.test.mjs` |
| An offline phone edit and a website edit meet by the conflict rule on the real app. | `rpmctl scenario web-sync-offline` |
| Browser `plan` commands use only the contract's task, entity, body and review ops; model and draft ops and planner Undo are refused, and a bad batch saves nothing. | `web/contract/command.schema.json`, `cloud-tests/planner.test.ts` (`applies plan ops and rejects model ops`), `cloud-tests/standaloneEdges.test.ts` (`rejects a bad planner batch`) |
| Planner snapshot v2 carries store-shaped `entries` and `planner` through a deep allowlist; credentials, tokens, traces, model payloads, Undo, conversations, memories and history stay local. | `web/contract/validate.mjs`, `android-companion/web-sync.test.mjs`, `android-companion/web-sync-plan.test.mjs`, `cloud-tests/planner.test.ts` (`deep record leaks`) |
| A command ID keeps one payload and one final result across retries and lost responses; reusing it for other content is refused. | `cloud-tests/planner.test.ts` (`keeps retries idempotent`, `returns a durable final receipt`), `cloud-tests/capture.test.ts` (`deduplicates commands`) |
| A revoked browser can't write, and work it already saved stays saved. | `cloud-tests/planner.test.ts` (`immediately revokes future writes`, `a revoked browser leaves applied work saved`), `cloud-tests/standalone.test.ts`, `SyncManagerTest.transportRejectsRevocationAndChecksConnectionAfterNetwork` |
| Browser linking uses hashed, one-use, ten-minute codes and revocable hashed tokens scoped to the phone's account. | `cloud-tests/webHttp.test.ts`, `cloud-tests/plannerRate.test.ts` |
| Conditional snapshot reads authenticate before returning 304; CORS and token quotas also apply to polling. | `cloud-tests/webHttp.test.ts`, `cloud-tests/plannerRate.test.ts` |
| Existing device pairing, events, and records survive additive account migration and token rotation. | `cloud-tests/webHttp.test.ts` |
| The phone's background sync runs the bundled replica with eval blocked and saves through the normal native load, save, pull and push bridge. | `android-companion/web-sync-runtime.test.mjs` with a simulated bridge, `PlannerCommandHostTest.bridgeTransportsJsonAndRefusesLegacyActionsOrAChangedConnection`; the Android background run stays UNVERIFIED until driven |
| The phone pushes and pulls with one connection's token, and a push resent with the same seq and part gets its first receipt back. | `SyncManagerTest.runsOneReplicaWithGuardsBeforeAndAfter`, `SyncManagerTest.transportPostsOnlyPushAndPullWithTheCapturedToken`, `SyncManagerTest.credentialsAreCapturedAsOneConnection`, `cloud-tests/standaloneEdges.test.ts` (`returns exactly the original nonempty part receipt`), `cloud-tests/planner.test.ts` (`recovers a lost response`) |
| Website Capture saves the user's exact words before the model runs and reads times in the user's time zone. | `cloud-tests/capture.test.ts` (`saves exact words`, `accepts the command timezone`, `creates one task at 5pm India`) |
| The website shows a row as "Saving" until the server answers and a snapshot that holds the change arrives. | `web/app/client.test.mjs`, `web/app/plan-queue.test.mjs`, `npm run web:drive` |
| The website resends an unsent change with the same command ID and body after a network failure or reload. | `web/app/client.test.mjs` |
| Every website action builds a command the contract accepts, on the snapshot revision the user saw. | `web/app/plan-queue.test.mjs` |
| A Project, Block or other record made in the browser keeps the UUID the browser gave it, unless that UUID is already in use. | `web/app/plan-queue.test.mjs`, `cloud-tests/standaloneEdges.test.ts` (`preserves supplied entity UUIDs`, `allocates unused server IDs`) |
| Convex stays at 1.48.0 or later. | `android-companion/web-sync-local.test.mjs` |
| Convex runs on Node 24: a `"use node"` action reads local time only inside `withTimeZone` (UTC reads listed with a reason), and every script that starts Convex (`dev`, `deploy`, `import`, `run`, `env`, a local backend) imports `scripts/web-sync/node24.mjs`; package scripts go through `scripts/web-sync/convex-cli.mjs`. | `scripts/rules/convex-node.test.mjs` |
| On the ChatGPT Site the planner opens without a link code: the Site holds the key, adds it only for `Bearer site`, never sends it to the page, and the page can't revoke it. The key reads the phone that synced last. | `web/site-worker.test.mjs`, `web/app/client.test.mjs`, `cloud-tests/webAdminSession.test.ts`, `npm run web:drive -- --no-code` |
| Local Convex reads credentials only from this worktree's `.env.local` and `.convex/`; its CLI home is `.verify/convex-home`, so it never falls back to `~/.convex` or another worktree. | `scripts/web-sync/worktree.test.mjs`, `.claude/skills/verify-rpm-glass/local-convex.test.mjs` |
| A prod Convex deploy goes through `npm run web:deploy-prod`: Node 24, an explicit `prod:` env file with inherited deploy keys cleared, a backup under an hour old (a Convex export passes its zip test, which skips unzip's zip-bomb check), zero pending `webCommands`, and a local rehearsal that refuses an empty website unless `--allow-empty-site`. | `scripts/web-sync/deploy-prod.test.mjs`, `scripts/web-sync/deploy-rehearsal.test.mjs` |
| `POST /v1/web/voice-token` needs a live browser key and an IANA time zone, refuses a setup from the browser, builds the Live setup on the server, mints a one-use token, gives each account 30 an hour (then 429 with `Retry-After`), answers `voice_unavailable` with no key, and never returns the key or the upstream error. | `cloud-tests/voice.test.ts` (`POST /v1/web/voice-token`) |
| A voice capture (`source: "voice"`) is a journal of the heard words: it applies at once, keeps the words exactly, retries idempotently by command id, and never schedules the text model. | `cloud-tests/voice.test.ts` (`voice capture is a journal of the words`) |
| One ramble is one plan command with one Undo: it carries the browser's new task ids with `exactTaskIds`, the server refuses it whole (saving nothing) when it would pick other ids, and the snapshot's `nextTaskId` makes the browser count like the server. The words are saved before the plan, on the same base revision. | `cloud-tests/voice.test.ts` (`one ramble is one plan command`), `web/app/plan-queue.test.mjs`, `web/app/voice-capture.test.mjs` |
