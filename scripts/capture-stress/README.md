# Stress-test Capture rambles

The target checkout needs its dependencies installed, for example with `npm ci` in that checkout. The runner never reads app key files. `--transport cli` is the default. For CLI runs, strict custom-prompt-only isolation is UNVERIFIED because CLI runtime instructions can remain even with safe mode. The canary check covers project documents and hooks. `isolation.json` retains the model's report of foreign instructions.

After improving an expectation, recheck retained outputs without making model calls with `node scripts/capture-stress/recheck.mjs .verify/capture-stress/RUN-DIRECTORY`. It preserves the previous results and an evaluation history. It refuses changed case words or turn order. `blockWords` checks that a task belongs under the named Result. `focusRetained` checks surviving proposal IDs; removal checks also require every survivor's fields to remain unchanged. Task insertion may renumber priorities, so unsolicited order checks compare relative order among seeded tasks.

Run from this checkout with an authenticated Claude CLI on PATH.

```powershell
npm run stress:capture
npm run stress:capture -- --hardest --repeat 3
npm run stress:capture -- --repo C:\Repos\rpm\OTHER-WORKTREE --concurrency 3
npm run stress:capture -- --only dinner-exact-four-turns,monologue-loan --repeat 3 --judge
```

To use the phone's Anthropic request body directly, select `--transport api`. The API transport reads only `process.env.ANTHROPIC_API_KEY`, inside each call. With an `anthropic` entry in the OS secret store, run these commands. `secret list` lists names without values. Replace the entry name if your stored name differs.

```powershell
secret list
secret run --env ANTHROPIC_API_KEY=anthropic -- npm run stress:capture -- --transport api --concurrency 3
secret run --env ANTHROPIC_API_KEY=anthropic -- npm run stress:capture -- --transport api --hardest --repeat 3 --concurrency 3
```

API runs send paid requests. They skip the CLI version check and isolation probe, and record both as skipped. `--judge` and `--probe-only` require CLI transport. The API transport makes no retries and has no OpenRouter fallback. Production application repair and escalation can still request another model call. Phone fallback behavior remains UNVERIFIED.

The target's `claudeRequest`, `providerSchema(TURN_SCHEMA)`, production prompt, input, and route settings construct the API body. Tests compare the resulting body with the production `nativeModelTransport` for all four routes. The endpoint, JSON content type, `x-api-key` header, `anthropic-version: 2023-06-01`, and redirect refusal match `ModelGateway.java`. No cache directives are added. The key appears only in the HTTP header and is never copied to a prompt, record, or artifact. Provider failure bodies and raw fetch exceptions are discarded. Failed calls retain HTTP status when received, elapsed time, stop reason and sanitized usage when available. Local response-validation messages preserve the phone's repair hint, with any credential value redacted. Script faults still pass through `userMessage` as faults.

Node fetch uses one total deadline bounded by the route's remaining time and 95 seconds. The quick, careful, long, and hard route budgets are 25, 35, 90, and 90 seconds. Plain fetch cannot reproduce Java's separate 8-second connection timer and 95-second per-read timer. API diagnostic results therefore do not prove phone networking behavior.

API cost estimates use [Anthropic pricing](https://platform.claude.com/docs/en/about-claude/pricing), verified on 2026-10-19. Haiku 5.5 rates per million tokens are $0.10 input, $0.50 output, $0.01 cache read, $0.125 five-minute cache write, and $0.20 one-hour cache write. Above 100,000 total input tokens, Haiku rates multiply by five. Sonnet 5.5 rates are $2 input, $10 output, $0.10 cache read, $2.50 five-minute cache write, and $4 one-hour cache write. Uncached input, cache read, and cache write tokens contribute to the threshold. Cache writes use the reported TTL breakdown, or the default five-minute rate when no breakdown is reported. Missing input or output usage produces `costUSD: null` and an incomplete total, never a free-call claim. Estimates are not billing receipts.

The corpus and checkers come from this checkout. `--repo` selects the entire target app implementation, including its prompt, schema, service, harness, model policy, interpreter, time guards, planner adapter and seed generator. It does not alter either checkout. No emulator, phone or app key file is used. `--help` lists all options. A failed expectation exits 1; a runner failure exits 2. Each run uses a new `.verify/capture-stress/<run-id>` directory unless `--out` is supplied. Use a new output directory each time.

The ramble fix preserves the three dinner cases' words but corrects their navigation and expectations. An Edit focus persists across typed turns until the draft closes. Removal turns now auto-apply like Capture; explicit `deferApply` remains available for draft-stage tests. In the exact four-turn case, `Both` removes both proposals immediately, and the later `First` cannot reverse that choice. The separate first-only case requires the second proposal and its original fields to survive. A missing draft fails removal checks, and structured clarification prompts count as visible questions. Historical pass rates used the earlier expectations and checker, so compare their individual failures as well as the totals.

CLI transport first probes isolation with a parent `CLAUDE.md` canary, hook canaries and a custom system nonce. It starts Claude in an empty temporary directory, with tools, MCP, skills and persistence disabled. `--bare` is attempted first. In Claude CLI 2.1.303 it disables OAuth and returns “Not logged in” on this machine. The runner then uses the existing login with `--safe-mode --restricted --setting-sources ""`. These flags disable project customizations and hooks. The CLI's own `StructuredOutput` formatting tool remains available. The probe records that distinction and stops the run if foreign instructions or a hook are observed. It cannot inspect hidden provider instructions.

Each case/repeat owns a file-backed, versioned store. The fixture reuses `scripts/gauntlet/seed.mjs`, which rpmctl uses, and replaces its tasks with six stable targets. The dentist is a read-only calendar fixture. Water, meals, Result groups and two drafts are seeded. The product clock starts at Monday 19 October 2026, 10 am IST, and advances one second per turn. System latency uses a separate wall clock.

`createIntentService` and `createCaptureAgent` drive the real application backend. The injected model sends the target's production prompt, schema and exact harness input through the selected transport. No new app seam or behavior is added. Production route selection, deadlines and repair/escalation remain active. CLI startup, extra formatting turns, caching and thinking can differ from the phone's API call. Reports label each run **CLI transport** or **API transport**. Native networking, provider fallback, notification delivery and UI remain UNVERIFIED.

Captures of at least 1,500 characters now get Haiku high with a 90-second deadline and the same 6,000-token budget; native Haiku reads permit 95 seconds. Short routes retain their existing deadlines. The CLI does not enforce the API's output-token cap, so successful long CLI captures do not prove the phone's latency or token sufficiency. Cancellation waits for the child process to exit before cleanup; cleanup failures preserve the original transport error.

`rambles.json` lists the split corpus and the ten hardest case IDs. Each case has `turns` and `expect`. A turn has `text`, optional `focus` (`dinner` or `previous`), and optional `deferApply`. Ordinary turns auto-apply through the Capture agent. Deferred turns explicitly exercise the draft stage through the same service and harness. A focused draft must remain active; the runner does not revive a committed draft.

Expectations describe canonical saved state by default. `created` matches title words by exact token or prefix and can require an entity, local `day`/`time`, `purposeWords`, `must` or `alert`. All words must match, and each expected item consumes a different row. `forbidden` rejects retracted titles in saved rows and pending proposals. `maxNew` counts new active tasks and planning entities. `changes` checks existing target IDs and fields; every other seeded item must retain its meaningful fields. `unchanged` gives explicit focus controls. `focusRemoved` checks operation IDs in the effective focused draft. `health` checks actual water and meal records. `question` is allowed, required or forbidden. Optional `checkpoints` run the same assertions at a numbered turn. `scope: "draft"` explicitly checks pending proposals instead of saved rows.

Execution checks cover schema validation, durable exact words before model work and after later turns, crashes, raw script faults, application failures and repeated questions. `npm test` includes negative controls and an injected model test that exercises real persistence, interpretation, canonical application and `userMessage` fault handling without calling a model. Rule checks cover the production error formatter's use. A safe backend error is still an evaluation failure if interpretation or application failed.

Every case directory contains the seed, current/final store, per-turn inputs, model outputs, traces and assertions. `results.json` and `report.md` aggregate pass rates, overlapping failure classes, routes, latency and usage. Token fields retain uncached input, output and cache counts separately. Dollar figures use CLI-reported estimates or API token usage and published rates, not billing receipts. A killed process may report no usage; do not interpret missing usage as free. An optional isolated Sonnet judge in CLI mode scores meaning without changing deterministic verdicts. It sees the seeded entities and all canonical saved entities after the capture, including edited existing tasks, as well as new tasks, body logs and draft receipts. It never sees the developer's reasoning or code changes. Fuzzy mismatches still need inspection before treating the overall rate as a product-quality estimate.
