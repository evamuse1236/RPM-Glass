# Capture rules and what enforces them

Rules for Capture: the composer, cards, the interpreter (`intent-v2`), the model calls, traces and `npm run capture`. AGENTS.md points here. Add a row when a correction becomes a check.

| Rule | Enforced by |
|---|---|
| When the Capture card list shrinks (keyboard open), it scrolls so a question's choices stay in view. | `android-companion/capture-presentation.test.mjs` (`choicesScrollTop`) |
| Capture saves the user's exact words before anything else, with or without an AI key, and keeps them for Retry when the model fails. A stale or closed focus never rejects the words: they are saved, the card says so, and Retry reads them on their own. | `rpmctl scenario capture-keeps-words`, `android-companion/capture-agent.test.mjs`, `android-companion/capture-session.test.mjs`, `chat-prototype/composer.test.mjs`, `intent-v2/test/capture-input.test.mjs` |
| What a message points at is decided once, when its words are saved: an Edit tap wins; otherwise a reply inherits the draft and open question of the capture that asked. The model sees that draft with the question and choices the person saw. | `intent-v2/test/conversation-focus.test.mjs` |
| Removal follows one table (`intent-v2/src/removal.mjs`): a task goes to Trash, a draft is set aside (Resume brings it back), an alarm turns the task's alert off, a calendar event is refused in plain words. The interpreter checks it and the prompt's removal rules are written from it. A task and a draft removed together are one change with one Undo that restores both. | `intent-v2/test/removal.test.mjs`, `android-companion/capture-session.test.mjs` |
| Every model attempt's trace keeps what it was given without words or keys: message IDs, roles and hashes, focus, question and choice IDs, entity IDs, what was cut, and the request's size and hash. | `android-companion/capture-trace.test.mjs`, `intent-v2/test/capture-input.test.mjs` |
| A chip's request ID is a short hash of the tap (`actionIdFor`), never the answer's own words, so every answer the model offers can be tapped. Choice chips too. | `android-companion/capture-answer.test.mjs`, `android-companion/capture-conversation.test.mjs` |
| "Which one?" is a choice question saved on the capture (ID, revision, action, two to four choices naming the items). All operations from a clarification response wait, and the focused draft waits to apply until the question is answered. A tap or a reply such as "both", "all", "first", "last" or a label word is read without the model and goes through `interpretTurn`; "that one" counts only after an Edit tap. Unsure replies go to the model with the question in view; expired, invented or repeated taps change nothing. | `intent-v2/test/choice-reply.test.mjs`, `android-companion/capture-conversation.test.mjs`, `android-companion/proposal-removal.test.mjs` (`an amend clarification never applies the focused proposals; Both sets them aside with one Undo and Resume`) |
| Removing a proposal keeps surviving proposals pending with their original guards. Mixed amendments refresh sources and time previews; a draft-only receipt offers Undo without overwriting later edits. | `intent-v2/test/proposal-removal.test.mjs`, `android-companion/proposal-removal.test.mjs` |
| A tap that fails on a Capture card says why on that card (`withProblem`), not only in the status line. | Judgment: `verify-rpm-glass` drive of a rejected answer (no automated check yet) |
| Capture applies what it reads: new items with a receipt and Undo, changes to saved items with Keep or Undo, deletes to Trash; every capture writes one trace without the key. | `android-companion/capture-agent.test.mjs` |
| Capture logs current water and meals through `editPlan`, with one receipt and Undo for mixed body/task changes. Skipped meals stay out of usual foods and nutrition guesses. | `android-companion/capture-body.test.mjs`, `android-companion/body-store.test.mjs` |
| In a reminder, a bare count after "in" means minutes; explicit units win. Standalone subjectless relative reminders save as Reminder or Alarm and offer Name it afterwards. Bare clocks resolve locally by the next-12h rule or stated-day waking hours, with a guarded Make it AM/PM receipt chip. | `intent-v2/src/short-reminder.mjs`, `intent-v2/test/short-reminder.test.mjs`, `android-companion/capture-short-reminder.test.mjs`, `scripts/capture-stress/smart-evidence.test.mjs` replays all ten original API outputs; live corpus `scripts/capture-stress/corpus/smart.json`; on the app, `rpmctl scenario capture-short-reminder` (runs on GitHub Actions) |
| Capture's supported entity operations and fields generate both its schema and its model-facing capability descriptions. Bare personal actions are captured as tasks even when RPM cannot perform them. Explicit external-execution requests name the limitation and offer one supported alternative. | `intent-v2/src/capabilities.mjs`, `intent-v2/test/capabilities.test.mjs`; personal-action and unsupported-request classification also require live model checks |
| Optional receipt help never blocks the original save. Name it targets the saved task ID; scheduling rechecks the target, time and calendar on tap. A consumed chip stays consumed after Undo. "Drank water" logs one glass; feedback reads saved counts and nudge rules. | `android-companion/capture-next-step.test.mjs`; phone rendering remains UNVERIFIED until driven |
| Undo after accepting a time clash never restores the adapter's temporary approval as a pending user proposal. Another action's reminder cannot authorize minutes for an unrelated task. | `android-companion/capture-short-reminder.test.mjs` |
| With no open question or focused draft, a bare "Both", "First" or "That one only" cannot invent a new choice about unrelated saved items. Parent links are optional; Capture never needs to invent a parent for a requested Goal. | `intent-v2/test/short-reminder.test.mjs`, capability registry; goal interpretation is also exercised by the live `goal-not-action` corpus case |
| `npm run capture` uses the phone's Capture service, agent, transport, guards, application and Undo. Its local file has one owner; no-key captures keep exact words and `/trace` exports no words or keys. | `cli/capture.test.mjs`, `cli/capture-session.mjs` |
| A rejected time keeps the supported actions and any earlier draft time. Its receipt names the time that was not applied; a failed repair keeps the checked parts. | `android-companion/capture-partial.test.mjs` |
| Stated morning, noon and spoken clocks pass the time guard. A bare clock at 5 through 11 with plainly morning words uses AM; evening words use PM. Without a stated day, a passed semantic time moves to tomorrow. Other bare clocks use the next occurrence within 12 hours, or waking hours on a stated day. Inference uses the action's exact evidence, records its rule and keeps a guarded flip chip. Clock-only follow-ups retain a saved future day; a stated new day wins. Another action's period cannot authorize a clock. | `android-companion/intent-time-guard.test.mjs`, `android-companion/capture-time-followup.test.mjs`, `cli/bare-clock.test.mjs`, `android-companion/capture-bare-clock.test.mjs`, `android-companion/capture-smart-regressions.test.mjs`; live `corpus/round3.json` |
| Captures the phone cannot read locally use Claude Haiku 5.5; re-planning, sorting, advice and changes to more than three items use Claude Sonnet 5.5 at high effort. A reply to an open question, or about the draft in focus, that the phone could not read on its own uses Haiku at high effort. Long Haiku and Sonnet have 16,000 output tokens, including thinking, within a 90-second route and 95-second native read limit; quick Haiku keeps 4,000 and careful Haiku 6,000. Both models are on the native allowlist. | `intent-v2/test/model-policy.test.mjs`, `app/src/test/java/com/rpm/prototype/ModelLimitsTest.java`, `scripts/capture-stress/api.test.mjs` (every route fits the native cap) |
| A stated result or reason for an action stays in its purpose, without becoming another task; independently requested actions stay separate. | `scripts/capture-stress/purpose.test.mjs` checks the historical bad-output fixture, purpose persistence and independent actions. Model classification requires the real API `hinglish-kal-subah` replay; fixtures do not prove it. |
| Capture asks Claude (Anthropic API key) first and tries OpenRouter once when Claude has no key, is unreachable, or answers 401, 403, 429 or 5xx; the trace records which service answered. | `intent-v2/test/model-services.test.mjs`, `ModelLimitsTest.java` |
| A new Capture title starts with a capital letter while preserving mixed casing such as iPhone and the rest of the user's spelling. Local and model reads use the same title boundary. | `android-companion/capture-smart-regressions.test.mjs`, `scripts/capture-stress/round3.test.mjs` |
| An item without a duration is a moment and never overlaps another task or a calendar event, on either side of the check. Explicit durations still clash. | `android-companion/capture-smart-regressions.test.mjs`, live `round3-moment-*` stress cases |
| Capture cards show facts as icon chips, and a receipt shows the task's alert. | `android-companion/capture-lines.test.mjs` |
| A page loads the saved data again only when it changed: it sends the version it holds, and the phone answers "unchanged" instead of sending the data. Its copy is what was last loaded or saved, never unsaved edits. Saves keep the version check. ("set a reminder in 5" went from 13.4 s to 2.7 s on the emulator.) | `android-companion/stored-copy.test.mjs`, `CompanionStoreLoadTest.java`, `rpmctl scenario capture-short-reminder` |
| The near-future Hinglish window “thodi der mein”, and meal and bedtime windows such as “after lunch” and “before bed” save today without an invented clock unless another day or an open-ended window was stated. The original phrase stays in the interpretation. | `android-companion/capture-vague-time.test.mjs`, `android-companion/capture-spoken-correction.test.mjs`; live `everyday-after-lunch` and `adv-hinglish-thodi-der` corpus cases |
| Equal task or Block creates in one response collapse into one. Child links follow the retained operation. Different schedules, parents and purposes remain separate. | `intent-v2/test/duplicate-creates.test.mjs` |
| A strict “after [clock] today to tomorrow” bulk move, including after that boundary has passed, selects from the complete saved store, excludes the exact boundary, retains clocks and uses one transaction and Undo. More than 30 matches or recurrence falls back to the model without a partial local move. | `android-companion/capture-bulk-local.test.mjs` |
| Spoken hour/minute clocks and Hindi half-hour clocks retain exact evidence. A day-only correction may echo its target's unchanged saved clock; it cannot borrow or change that clock. | `android-companion/capture-spoken-correction.test.mjs`, `android-companion/intent-time-guard.test.mjs` |
| A literal single task can be read locally only without a focused draft, open question, open Block or possible saved-item match. Negation, alternatives, mixed actions, reasons, references, numeric titles and unsupported times fall back to AI. The normal receipt, saved words and Undo apply. | `android-companion/capture-local-reader.test.mjs` |
| Exact current water counts in glasses, including “drank 2 glasses” and “abhi do glass paani piya”, are read locally. Other drinks, estimates, historical reports, unsupported units and counts outside 1–30 fall back to AI. A matching daily aggregate does not identify a duplicated report. | `android-companion/capture-local-reader.test.mjs`, `intent-v2/test/capabilities.test.mjs`; mixed-report classification also requires live corpus checks |
| A named saved task's explicit due clock takes precedence over a conflicting relative nudge in the same correction. Another clause's past “kal” or part of day cannot block or authorize that action's clock. Quantities remain quantities. | `android-companion/capture-spoken-correction.test.mjs`, `android-companion/capture-bare-clock.test.mjs` |
| An explicitly essential action (“have to … otherwise …”) can be Must. A deadline or ordinary “need to” alone is not Must. A vent without a request needs acknowledgement without a follow-up question or new task. | `intent-v2/test/capabilities.test.mjs` (prompt contract), adversary live cases (model classification) |
| A single Inbox action keeps an explicit loss consequence or “the only way” reason when the model omits it. An explicit leading “I have to” or “must” with that reason can mark it essential. Existing fields, Block purposes, multiple actions, corrections and questions remain with the model. | `intent-v2/test/task-reasons.test.mjs` |
| A bare specific action cannot rewrite a saved task merely because both share a verb or broad category. A missing subject match is repaired before any save; explicit saved references still work. | `intent-v2/test/follow-up.test.mjs` |
| “Same time” with an exact new day preserves the saved clock even if the model renders a malformed inherited clock. A quoted due time cannot overwrite an explicitly cleared schedule. Vague-window and clock recovery retain the original source ownership during partial validation. | `android-companion/capture-spoken-correction.test.mjs` |
