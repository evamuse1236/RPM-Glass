# Brief: evams deadline adapter (backend, pure module + tests)

You are in a git worktree of the RPM repo on branch `feat/evams-deadline-adapter`. Work only in this worktree.

## Context
RPM is a personal planning app. Its Node CLI lives in `cli/`. The user's other project, evams, publishes a public JSON feed of ISDM LMS assessments at `https://evams.evamuse.chatgpt.site/api/site-data` (no login). Research on its shape: read `C:\Repos\rpm\RPM-Glass\docs\wayfinder\whole-day\research\evams-deadline-shape.md` first. Key facts from it: each assessment has `id` (`lms-<lmsContentId>`), `lmsContentId`, `title`, `course`, `dueDate`, `time` (12-hour text like "11:00 PM"), `submissionWindow.closesOn`, `status`, `lmsDateChange`. The real deadline is `submissionWindow.closesOn` + `time`, in India time (IST, UTC+05:30). There is no submitted flag.

How RPM will use these items (Result vs task, all-day vs 11:59 PM) is NOT decided yet. So build only the reading and diffing layer, and keep those choices out.

## Build
1. `cli/evams-deadlines.mjs`, pure ES module, no network inside the core functions:
   - `parseEvamsFeed(json)` → array of `{ sourceId: "evams:<id>", title, course, deadline: { date: "YYYY-MM-DD", time: "HH:MM" | null, utc: ISO string | null }, status, raw }`. `utc` is computed from IST when a time exists, else null. Skip items with no usable date and report them in a second return value `{ items, skipped: [{ id, reason }] }`.
   - `diffDeadlines(previousItems, nextItems)` → `{ added, changed: [{ before, after, fields: [...] }], unchanged, missing }`. `missing` = in previous but not in next (do NOT treat as deleted; the research says absence isn't deletion).
   - `fetchEvamsFeed(url = default, fetchImpl = fetch)` thin wrapper, the only network code.
2. `cli/evams-deadlines.test.mjs` using `node:test` + `node:assert/strict`. Cover: time parsing (12 AM, 12 PM, 11:00 PM, missing time, junk), IST → UTC across midnight, closesOn preferred over dueDate, stable sourceId, skipped items, diff cases. Use a small fixture file `cli/fixtures/evams-site-data.sample.json`: fetch the live feed once with curl, keep at most 8 assessments, and remove anything that looks personal (names, emails, roll numbers) — keep only the assessment fields above.
3. Run `npm ci` if node_modules is missing, then `npm run test:js`. All tests must pass, including the existing ones.
4. Commit on this branch with message "evams deadline adapter: parse and diff the public feed" and the trailer line `Co-Authored-By: GPT 6.1 Sol <noreply@openai.com>`. Do not push. Do not edit files outside `cli/`.
