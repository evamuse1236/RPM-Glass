# Capture API defect fixes, 19 October 2026

The authorized real Anthropic API rerun passed **9/9**, using nine Haiku calls and no repair or Sonnet calls. The three courier repeats each saved one task for 20 October at 8 AM IST, with the exact purpose `Parcel ka issue close karna hai bas.` and the original capture words retained. The six monologue repeats completed on their first long route.

## Root causes and changes

`intent-v2/src/model-policy.mjs:13` capped long Haiku output at 6,000 tokens. `app/src/main/java/com/rpm/prototype/ModelLimits.java:11` enforced that same ceiling for both native services. All eight historical monologue first attempts used exactly 6,000 output tokens; the later six explicitly recorded `max_tokens`. All eight required Sonnet repair. The failure was an application output ceiling, rather than a network failure or Haiku's model maximum.

The long route now permits 16,000 output tokens, and the native Haiku limit matches it. Quick Haiku remains 4,000, careful Haiku 6,000, and Sonnet 16,000. Model policy is `rpm-claude-v4`. The 90-second long-route deadline and 95-second native read timeout remain unchanged. Every rerun long call completed within 38 seconds. This verifies these cases, not a universal bound for every possible 16,000-token response.

[Anthropic documents a 128K maximum output and default adaptive thinking for Haiku 5.5](https://platform.claude.com/docs/en/models/haiku-5-5/overview). [Thinking consumes the response budget](https://platform.claude.com/docs/en/models/haiku-5-5/migration-guide). Historical artifacts retain usage and errors, but not raw response blocks, so their thinking/JSON split cannot be recovered. The transport now records only allowlisted block counts and character lengths before interpretation validation. All six successful long responses contained one thinking block and one JSON text block, with 4,358–5,215 text characters. The exposed thinking text length was zero. This does not mean zero thinking tokens; the API did not expose a token split. No raw thinking or signatures are retained by the added metadata.

`intent-v2/prompts/intent-system.mjs:10` now explicitly distinguishes a later stated result or reason from an independent action. The previous prompt separated ideas and reflections but did not explain this case. Its actual bad output classified the purpose sentence as an action, supplied two suggested translated task titles with null evidence, and omitted the first task's purpose. That structure can also describe two legitimate independent actions, so an interpreter filter cannot reliably repair it without another semantic decision. Prompt v4 reads the whole thought, stores the stated purpose on the relevant task, and preserves separately requested actions. It includes the incident and an independent courier/refund contrast.
